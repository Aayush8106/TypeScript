I used the following configuration:

```json
{
  "compilerOptions": {
    "rootDir": "./src-TS",
    "outDir": "./compiled-JS"
  }
}
```

**`rootDir`**

Specifies the root directory containing the TypeScript source files.

In this project, TypeScript source files are stored inside `src-TS/`.

**`outDir`**

Specifies where the compiled JavaScript files should be placed.

In this project, compiled JavaScript files are stored inside `compiled-JS/`.

This configuration helps keep TypeScript source code separate from the JavaScript generated by the compiler.

## 2. Type vs Interface

Both `type` and `interface` can describe the expected structure of an object.

They help TypeScript check whether an object contains the required properties with the correct types.

### Using `type`

```ts
type Product = {
    name: string;
    price: number;
    inStock: boolean;
};

const product1: Product = {
    name: "Phone",
    price: 9999,
    inStock: true
};
```

Here, `Product` defines the structure that an object must follow.

### Using `interface`

```ts
interface Product {
    name: string;
    price: number;
    inStock: boolean;
}

const product1: Product = {
    name: "Phone",
    price: 9999,
    inStock: true
};
```

This interface defines the same object structure as the previous example.

### What I Learned

- Both `type` and `interface` can describe object shapes.
- They allow TypeScript to check object properties and their types.
- An object must satisfy all required properties.
- An optional property can be omitted.
- `interface` is commonly used to describe the structure of objects.

The two approaches overlap, but they are not identical in every situation. For example, interfaces can be extended and merged through declaration merging, while type aliases can also represent unions and other types.

## 3. Optional Properties

An optional property is a property that an object does not have to contain.

TypeScript uses the `?` symbol to mark a property as optional.

### Example

```ts
interface Product {
    name: string;
    price: number;
    inStock: boolean;
    discount?: number;
}
```

In this interface, `name`, `price`, and `inStock` are required, while `discount` is optional.

### Object Without the Optional Property

```ts
const product1: Product = {
    name: "Phone",
    price: 9999,
    inStock: true
};
```

This object is valid even though it does not contain `discount`.

### Object With the Optional Property

```ts
const product2: Product = {
    name: "Phone-B",
    price: 6999,
    inStock: true,
    discount: 10
};
```

This object is also valid because it includes `discount` with a numeric value.

### What I Learned

- `?` makes a property optional.
- Optional properties do not have to be included when creating an object.
- If an optional property is supplied, its value must match the declared type.
- For example, `discount: "10"` is invalid when `discount` is declared as `number`.

### Another Example

```ts
interface User {
    name: string;
    age?: number;
}

const user1: User = {
    name: "Rahul"
};

const user2: User = {
    name: "Aayush",
    age: 22
};
```

Both objects are valid because `age` is optional.

## 4. Readonly Properties

The `readonly` modifier prevents a property from being reassigned through normal TypeScript-checked code after the object has been created.

### Example

```ts
interface Product {
    readonly id: number;
    name: string;
    price: number;
}

const product1: Product = {
    id: 1,
    name: "Phone",
    price: 9999
};
```

The `id` property is marked as `readonly`.

### Reading a Readonly Property

```ts
console.log(product1.id);
```

Reading the property is allowed.

### Changing a Readonly Property

```ts
product1.id = 3;
```

TypeScript reports an error because `id` is read-only.

However, other properties that are not marked `readonly` can still be changed:

```ts
product1.name = "New Phone";
product1.price = 8999;
```

These assignments are allowed.

### What I Learned

- `readonly` restricts reassignment of a property in TypeScript.
- A read-only property must still receive a value when creating an object if it is required.
- Read-only properties can be accessed and read normally.
- `readonly` is primarily a compile-time restriction. It does not automatically freeze an object at JavaScript runtime.

## 5. Arrays of Objects

An array can store multiple objects that follow the same interface.

TypeScript uses `User[]` to represent an array of `User` objects.

### Example

```ts
interface User {
    readonly id: number;
    name: string;
    age?: number;
}

const user1: User = {
    id: 1,
    name: "Rahul",
    age: 22
};

const user2: User = {
    id: 2,
    name: "Aayush"
};

const users: User[] = [user1, user2];
```

### Understanding the Code

- `user1` is a single object that follows the `User` interface.
- `user2` is another object following the same interface.
- `users` is an array containing both objects.
- `User[]` tells TypeScript that every array element must be compatible with the `User` interface.

Because `age` is optional, `user2` does not need an `age` property.

### Displaying the Array

```ts
console.log(users);
```

This displays the array containing both user objects.

### What I Learned

- `User` describes the structure of one user object.
- `User[]` describes an array of user objects.
- TypeScript checks the objects added to a typed array.
- The array can contain multiple objects with the same structure.
- Optional properties allow objects to have different sets of properties while still satisfying the interface.

## 6. Functions and Return Types

Functions can accept parameters with declared types. We can also specify what type of value a function returns.

### Example With a `void` Return Type

```ts
function displayUsers(users: User[]): void {
    console.log(users);
}
```

### Understanding the Function

**`displayUsers`**

This is the function name.

**`users: User[]`**

The parameter named `users` must be an array of objects compatible with the `User` interface.

**`: void`**

The return type is `void` because the function is intended to perform an action rather than return a useful value.

**`console.log(users)`**

Displays the supplied array in the console.

### Calling the Function

```ts
displayUsers(users);
```

This calls the function and passes the `users` array to it.

### What I Learned

- Functions can receive typed parameters.
- A function can accept an array of typed objects.
- The return type can be explicitly declared.
- `void` indicates that a function is not intended to return a meaningful result.
- Calling a function executes its code.

## 7. The `for...of` Loop

The `for...of` loop is used to iterate over the values in an iterable, such as an array.

Instead of displaying the entire array at once, I used a loop to process each user individually.

### Example

```ts
function displayUsers(users: User[]): void {
    for (const user of users) {
        console.log(user);
    }
}
```

### Understanding the Loop

**`for (const user of users)`**

- `users` is the array being iterated over.
- `user` represents the current element in the array.
- `const` declares the loop variable for each iteration.
- The loop body runs once for every user in the array.

**`console.log(user)`**

Displays the current user object.

### Example Function Call

```ts
displayUsers(users);
```

The loop processes each user in order, so Rahul and Aayush are logged separately.

### What I Learned

- `for...of` iterates over array values.
- Each iteration provides the next element.
- It is useful for processing every object in an array.
- It can be combined with typed arrays and functions.

## 8. TypeScript Errors in VS Code

While practicing, I tested what happens when an object contains a value that does not match its declared type.

### Example

```ts
interface Product {
    name: string;
    price: number;
    inStock: boolean;
}

const product1: Product = {
    name: "Phone",
    price: "9999",
    inStock: true
};
```

The `price` property is declared as a number, but the object provides a string.

TypeScript reports a type error.

### Correct Version

```ts
const product1: Product = {
    name: "Phone",
    price: 9999,
    inStock: true
};
```

The value `9999` is a number because it does not have quotation marks.

### TypeScript vs JavaScript

| TypeScript (`.ts`)                                    | JavaScript (`.js`)                                              |
| ----------------------------------------------------- | --------------------------------------------------------------- |
| Checks declared types during type checking.           | Does not enforce TypeScript type annotations.                   |
| Can report type mismatches.                           | Runs without TypeScript's static type checks.                   |
| Supports interfaces and other TypeScript-only syntax. | Does not support TypeScript interfaces as runtime declarations. |

TypeScript's type information is erased during compilation. Therefore, the generated JavaScript does not retain the same type-checking rules.

Depending on compiler settings, TypeScript may still emit JavaScript even if type errors exist.

To prevent JavaScript from being emitted when compilation has errors, the following option can be added to `compilerOptions` in `tsconfig.json`:

```json
{
    "compilerOptions": {
        "rootDir": "./src-TS",
        "outDir": "./compiled-JS",
        "noEmitOnError": true
    }
}
```

### What I Learned

- TypeScript checks whether values match declared types.
- VS Code can display TypeScript errors while editing.
- JavaScript does not enforce TypeScript interfaces or type annotations.
- Compiled JavaScript is the code executed by Node.js or the browser.
- Compiler settings determine whether output is emitted when errors exist.

## 10. Complete Project Code

The following is the complete code for `src-TS/user-management.ts`.

```ts
interface User {
    readonly id: number;
    name: string;
    age?: number;
}

const user1: User = {
    id: 1,
    name: "Rahul",
    age: 22
};

const user2: User = {
    id: 2,
    name: "Aayush"
};

const users: User[] = [user1, user2];

function displayUsers(users: User[]): void {
    for (const user of users) {
        console.log(user);
    }
}

displayUsers(users);
```

### Code Explanation

**Step 1 — Define the interface**

```ts
interface User {
    readonly id: number;
    name: string;
    age?: number;
}
```

Defines the properties and types of a user object.

**Step 2 — Create the first user**

```ts
const user1: User = {
    id: 1,
    name: "Rahul",
    age: 22
};
```

Creates a user with an ID, name, and age.

**Step 3 — Create the second user**

```ts
const user2: User = {
    id: 2,
    name: "Aayush"
};
```

Creates a user without an age, demonstrating that the property is optional.

**Step 4 — Store both users**

```ts
const users: User[] = [user1, user2];
```

Creates an array containing both user objects.

**Step 5 — Define the display function**

```ts
function displayUsers(users: User[]): void {
    for (const user of users) {
        console.log(user);
    }
}
```

Receives a user array and logs each user individually.

**Step 6 — Call the function**

```ts
displayUsers(users);
```

Executes the function using the array of users.

## 11. How to Compile and Run

Open the terminal in the `Day-3/Normal/` directory.

### Compile TypeScript

```bash
npx tsc
```

Alternatively, if TypeScript is installed and `tsc` is available in the terminal:

```bash
tsc
```

The compiler uses `tsconfig.json` and writes JavaScript output to `compiled-JS/`.

### Run the Program

```bash
node compiled-JS/user-management.js
```

This executes the generated JavaScript using Node.js.

### Check for Type Errors Without Emitting JavaScript

```bash
npx tsc --noEmit
```

This checks the TypeScript files without generating JavaScript output.
